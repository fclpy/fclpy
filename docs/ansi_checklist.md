## How to use this

**Do not work this list top-to-bottom.** It is ordered by failure count so
that *clusters* are visible; a file with 90 failures is nearly always one
missing mechanism, not 90 bugs. Pick a cluster, find the mechanism, fix it,
then re-run just that file or directory:

```powershell
pipenv run python scripts/run_ansi.py <group>            # whole directory
pipenv run python scripts/run_ansi.py <group>/<file>.lsp # single file
pipenv run python scripts/ansi_checklist.py              # regenerate this
```

A full-suite run takes ~113 minutes and is **not** required to verify a fix.
Run it to move the official scoreboard or close a milestone.

load time by macros, e.g. `cons/cxr.lsp` builds 40 of its tests with
``(eval `(deftest ,(intern ...) ...))``.

**They are still reachable by targeted runs.** Loading the file whose
macros generate them registers and runs them exactly as the full suite
does -- only this checklist's *static attribution* misses them, not the
runner. A consequence worth knowing: `run_ansi.py <file>` normally
reports **more** registered tests than this checklist attributes to that
file (cxr.lsp: 176 registered vs 136 attributed here). **The targeted
run is the authority for a file; this checklist is an index, not a
count.**

Run with `--detail` to list them.
